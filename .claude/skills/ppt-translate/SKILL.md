# PPT 번역 (번역팀)

담당: 번역팀 과장 **송하린** (번역 실무) · 팀장 **차유진** (원문보존 검수).
보고 경로는 다른 직원과 같다: 송하린 → 차유진 팀장 → 본부장 → 대표.

## 대원칙 — 번역만 한다

대표님 지시: **"다른 언어로 번역만 하는 거지 그 이상은 수정하면 안 된다."**

이건 품질 기준이 아니라 **금지 사항**이다. 다음은 전부 위반이다.

- 내용을 더하거나 빼는 것
- 어색한 문장을 "더 좋게" 다듬는 것 (윤문 = 훼손)
- 문장 순서·슬라이드 순서·장수를 바꾸는 것
- 글꼴·크기·색·정렬·여백·이미지·도형·애니메이션을 건드리는 것
- 숫자·단위·통화를 환산하는 것 (USD → 페소 금지)
- 브랜드명·인명·규정명(ANMAT, CPNP, GMP, CFS)·HS코드를 번역하는 것

원문이 틀렸다고 생각되면 **고치지 말고 보고서에 적어 올린다.** 판단은 대표님이 하신다.

## 왜 이 방식이 안전한가

`.pptx` 는 사실 ZIP 이고, 화면에 보이는 글자는 전부 `<a:t>` 태그 안에 있다.
도구는 그 안의 글자만 갈아 끼우고 나머지 바이트는 손대지 않는다.
**레이아웃을 망가뜨리는 것이 구조적으로 불가능하다** — 다른 번역 도구처럼 슬라이드를 다시 그리지 않는다.

`apply.js` 는 만든 뒤 원본과 대조해서 "번역 대상이 아닌 파일이 하나라도 바뀌었는지" 스스로 검사한다.
검사가 실패하면 종료코드 2 로 멈춘다.

## 작업 순서

대표님이 번역실 업로드 버튼으로 올리신 파일은 `tools/translate/inbox/` 에 있고,
요청 내용(언어·주의사항)은 `data/homework.json` 의 `대기` 건에 들어 있다.

```
1) node tools/translate/extract.js "tools/translate/inbox/<파일>.pptx"
   → tools/translate/work/<파일>.strings.json 생성 (원문만 뽑는다. 파일은 안 건드린다)

2) strings.json 의 각 unit 의 t 에 언어별 번역문을 채운다
   { "id": 12, "where": ["슬라이드 3"], "text": "원문", "t": { "es-AR": "번역문", "en": "..." } }
   · text 는 절대 고치지 않는다
   · 한 파일에 여러 언어를 같이 채울 수 있다 (원문 추출은 한 번만 하면 된다)

3) node tools/translate/apply.js "tools/translate/inbox/<파일>.pptx" \
        tools/translate/work/<파일>.strings.json --lang es-AR
   → tools/translate/out/<파일>.es-AR.pptx
   언어마다 한 번씩 돌린다.

4) 렌더해서 눈으로 검수한다 (문서제작실과 같은 도구를 쓴다)
   powershell -ExecutionPolicy Bypass -File tools/docgen/render.ps1 -Path <번역본>
   node tools/docgen/pdf2png.js <pdf> 2
   → Read 로 PNG 를 열어 직접 본다

5) 검수를 통과한 파일만 files/ 로 복사한다 (사이트가 files/ 를 서빙한다 → 대표님이 내려받으신다)
```

## 검수 항목 (차유진 팀장)

렌더한 이미지를 눈으로 보고 확인한다. 번역문만 읽고 넘어가지 않는다.

| 볼 것 | 왜 |
|---|---|
| **글자 넘침 · 잘림** | 스페인어·독일어는 한국어보다 40~80% 길다. 상자를 벗어나면 대표님께 보고한다 (상자를 늘리는 건 원본 수정이다 — 임의로 하지 않고 지시를 받는다) |
| **용어 통일** | 같은 제품·성분을 슬라이드마다 다르게 부르면 바이어가 다른 물건으로 읽는다 |
| **고유명사 원문 유지** | AURAKOREA, Dr.SANTE, ANMAT, CPNP, HS코드, 인명 |
| **숫자·단위·통화** | 원문과 한 글자도 달라지면 안 된다 |
| **서식 섞인 줄** | `extract.js` 가 `mixed: true` 로 표시한 줄. 한 문장 안의 굵게/색 강조가 첫 서식으로 흡수된다. 강조가 사라졌으면 보고한다 |
| **빈 슬라이드 · 사라진 글자** | 장수와 글상자 개수가 원본과 같은지 |
| **RTL 언어(아랍어)** | 글자만 바꾸므로 문단 방향은 왼쪽→오른쪽 그대로다. 아랍어 납품 전 반드시 대표님께 알린다 |

## 3대 언어 지침

`data/langs.js` 에 목록이 있다. 그중 대표님이 주기적으로 쓰시는 세 언어:

**스페인어 (아르헨티나) `es-AR`** — 스페인 본토와 다르다.
- voseo (tú 가 아니라 vos), 현지 상관례 용어를 쓴다
- 화장품 규제는 ANMAT 기준 용어로 (스페인의 CPNP 용어를 끌어오지 않는다)
- 소수점·천단위 표기가 한국과 다르지만 **원문 숫자는 그대로 둔다**

**영어 `en`** — 무역 실무 영어. 화려한 마케팅 문구로 바꾸지 않는다.
- Incoterms(FOB, CIF, DDP), MOQ, Lead time 등 업계 표준 용어를 쓴다

**한국어 `ko`** — 외국어 자료를 대표님이 읽으실 때. 존댓말 보고체로 옮기되 내용은 그대로 둔다.

목록에 없는 언어도 코드만 주면 된다 — `--lang` 은 어떤 문자열이든 받는다.

## 도구

`tools/translate/` (Node, CommonJS). **새로 설치할 것이 없다** — jszip 은 `tools/docgen` 에 이미 있고 그걸 그대로 쓴다.

| 파일 | 하는 일 | 토큰 |
|---|---|---|
| `extract.js` | 원문 뽑기 (중복 문구는 하나로 합친다) | 0 |
| `apply.js` | 번역문 되돌려 넣기 + 원본 대조 검사 | 0 |
| `lib.js` | 공용 로직 (`<a:t>` 훑기·되쓰기) | — |
| `selfcheck.js` | 도구 자체 점검 (왕복 검사) | 0 |

도구를 고쳤으면 **반드시** `node tools/translate/selfcheck.js` 를 돌려 통과시킨다.

토큰이 드는 건 2단계(번역문 작성) 하나뿐이다. 그래서 `extract.js` 는 같은 문구를 하나로 합쳐 둔다 —
같은 덱을 다른 언어로 또 번역할 때는 원문을 다시 뽑지 않고 같은 strings.json 에 언어만 추가한다.

## 이미 겪은 함정

- **run 쪼개짐**: PowerPoint 는 한 문장을 `<a:r>` 여러 개로 쪼개 둔다("안녕"+"하세요").
  run 하나씩 번역하면 반드시 엉터리가 된다. 도구는 `</a:p>` 와 `<a:br/>` 를 경계로 묶어
  **한 줄 통째로** 번역 단위를 만든다. 이 단위를 임의로 쪼개지 않는다.
- **앞뒤 공백**: run 끝의 공백 하나로 단어를 띄우는 슬라이드가 있다. `apply.js` 가 원문의 앞뒤 공백을
  그대로 다시 붙인다. 번역문에 공백을 억지로 넣지 않는다.
- **`.ppt`(구형)**: 받지 않는다. PowerPoint 에서 `.pptx` 로 저장해 달라고 대표님께 말씀드린다.
- **파일은 로컬 전용**: 대표님이 올리신 원본과 번역 결과는 `.gitignore` 되어 저장소에 올라가지 않는다.
  그래서 클라우드 자동 루틴은 번역 건을 처리할 수 없다 (`homework.json` 의 `local: true` 로 표시된다).
  번역은 사무실 PC 에서 처리한다.
