# 사무실 화면 검수

**고쳤으면 반드시 찍어서 본다. 눈으로 확인하지 않은 화면은 대표님께 올리지 않는다.**

이 규칙이 없어서 방이 겹치거나 글자가 잘린 걸 대표님이 먼저 발견하신 일이 반복됐다.
("너가봐봐 딱봐도 이상하잖아") 이제 도구가 있으니 그럴 일이 없어야 한다.

## 1. 화면 찍기

```
node tools/shot.js                                  # 전체 화면 (대표님 모니터 1907×902 기준)
node tools/shot.js <출력경로> <가로> <세로>
```

환경변수로 확대 검수:

| 변수 | 뜻 | 예 |
|---|---|---|
| `SHOT_SEL` | 그 요소만 잘라서 찍는다 | `#docStudio`, `#hqRoom`, `#frontDoor`, `#room-mkt` |
| `SHOT_SCALE` | 해상도 배율 (세부를 볼 때) | `3`, `4` |

```powershell
$env:SHOT_SEL="#docStudio"; $env:SHOT_SCALE="4"; node tools/shot.js out.png; Remove-Item Env:\SHOT_SEL,Env:\SHOT_SCALE
```

dev-server(5500)가 떠 있지 않으면 알아서 띄웠다 내린다.
찍고 나면 **Read 로 PNG 를 열어 실제로 본다.** 안 보면 찍은 의미가 없다.

## 2. 눌러 보기

```
node tools/test-ui.js
```

문서제작실 · 요청 폼 · 작업지시서 · @ 자동완성 · 태그 지시 ·
결재 안건 열어 보기 · 보고 열어 보기 · **실제 파일 내려받기**까지 클릭해서 확인한다 (현재 29항목).
화면을 건드렸으면 이걸 통과시키고 올린다. 새 기능을 만들면 여기에 항목을 추가한다.

## 2-1. 대표님이 보실 창을 찍어 본다

```
node tools/shot-viewer.js     # 보고 내용 · 결재 안건 · 만든 문서 창 3종
```

대표님이 결정 전에 여시는 창이다. 글자 잘림·여백·버튼 위치를 반드시 눈으로 본다.

## 2-2. 이미지 여백 자르기

```
node tools/crop.js <이미지> [여백px]
```

PDF 를 이미지로 뽑으면 아래가 텅 빈 채로 나온다. 미리보기에 넣기 전에 잘라낸다.

## 3. 볼 때 확인할 것

- **겹침**: 방끼리, 방과 복도, 방과 안내데스크·유리벽
- **잘린 글자**: 방보다 내용이 크면 아래가 잘려 나간다. 특히 알약 라벨은 두 줄로 쪼개진다
- **빈자리**: 방은 큰데 안이 텅 비어 있지 않은지
- **캐릭터 위치**: 책상 위에 떠 있지 않은지 (자리 SVG 는 반드시 `viewBox="0 0 112 62"` 로 맞춘다.
  좌표계가 다르면 캐릭터가 뜬다 — 실제로 겪었다)
- **404**: shot.js 가 URL 까지 찍어 준다.
  `api/session-check` 와 `favicon.ico` 404 는 로컬에서 정상이다 (비밀번호는 배포 환경에만 있다)

## 4. 좌표를 바꿨을 때

`data/layout.js` 숫자를 바꿨으면 겹침부터 계산으로 확인하고, 그다음에 찍어서 본다.
방은 절대 좌표로 놓이므로 숫자가 곧 배치다. 눈으로만 맞추려 하지 않는다.
